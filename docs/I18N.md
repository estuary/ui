# i18n

## Status: react-intl is being retired

The app still ships `react-intl`, but the direction is to remove it, not to expand it.

**Rules for new and changed code:**

- Do not add new message keys to `src/lang/en-US/`.
- Write new copy as plain strings at the call site, or in a feature-level constants file when a feature centralizes its copy.
- Do not convert `<FormattedMessage>` to `useIntl()` — that older guidance is obsolete. The goal is removal, not an API swap.
- When you touch a component that uses `react-intl`, prefer to remove the dependency: resolve the string in the caller and pass it as a prop.

---

## Migration Scaffold: Named Export + Deprecated Wrapper

Many shared components (19 as of Aug 2026 — search for `@deprecated Prefer the named`) are split into two exports. PR #2009 ("Deprecate i18n props") started the pattern:

- A **named export** whose text prop is an already-resolved string. No `react-intl` inside.
- A **deprecated default export** that accepts the i18n message id, calls `useIntl().formatMessage`, and forwards the resolved string to the named component.

Example: `src/components/tables/cells/ExpandDetails.tsx`.

**Rules:**

- Keep both exports until every caller migrates to the named export. Do not collapse the pair into one intl-calling component — the wrapper looks like duplication, but it is the migration bridge.
- Put new functionality and styling in the core named component.
- When you touch a caller of a deprecated wrapper, migrate it to the named export with a pre-resolved string.

---

## Legacy Setup

This remains wired while removal is in progress. Maintain it; do not extend it.

`IntlProvider` is configured in `src/context/Content.tsx` (the outermost provider in `src/context/index.tsx`). Only `en-US` is implemented. Missing keys are logged to LogRocket as `CustomEvents.TRANSLATION_KEY_MISSING`.

Messages live in `src/lang/en-US/`, split by domain (`CommonMessages.ts`, `Errors.ts`, `Workflows.ts`, …). `index.ts` spreads all files into one flat `Record<string, string>` — keys must be globally unique across the directory.

IDs are lowercase and dot-separated (`domain.section.key`):

```
error.title
common.loading
workflows.error.initForm
routeTitle.captures
```
